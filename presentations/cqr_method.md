# CQR + Geometry：基于上下文 Q 回归的强化学习方案

## 方法原理（清晰版）

CQR（Contextual Q Regression）可以理解为“在给定上下文下，对候选动作的 Q 值做回归”。在本项目里，我们没有让模型直接从原始台面坐标输出连续击球参数，而是把问题拆成两步：

- 第一步：用几何规则生成一批“看起来物理上合理”的候选击球；
- 第二步：用 CQR 模型学习“在当前局面这个上下文下，每个候选的大致好坏（Q 值）”。

### 1. 数据生成：几何候选 + 物理仿真作为监督信号

离线数据生成阶段类似于搭建一个“题库”：

1. 从不同对局、不同时刻采样大量台面状态，作为不同的上下文；
2. 对每个台面，用幽灵球几何规则生成一批候选击球：
   - 遍历当前我方目标球和所有袋口；
   - 对每个“目标球–袋口”组合，通过幽灵球计算理论瞄准方向、切球角和相关距离；
   - 根据距离估算一个合理力度，并在附近做少量微调；
   - 过滤掉切球角特别极端、距离不现实的线路，得到几十个候选。
3. 对每个候选，调用物理引擎进行完整仿真：
   - 把候选中的力度、方向和旋转参数写入球杆；
   - 让环境模拟这一杆的全过程；
   - 用与其他方法一致的 `analyze_shot_for_reward` 函数为它打一个标量分数。

这样，我们就为每个“台面状态 + 候选动作”配上了一个真实的 reward，可以把它看成近似的“一步 Q 值”。这些带标签的数据会被用来训练 CQR 模型。

### 2. 特征与上下文：把几何直觉编码成输入向量

为了让模型更容易学习，我们不会直接把所有球的原始坐标、速度全部扔进网络，而是抽取了一组更接近人类直觉的特征：

- 候选本身的几何特征，例如：
  - 这条线路的切球角；
  - 母球到目标球的距离；
  - 目标球到袋口的距离；
  - 路径上是否容易被其他球挡住，或者与其他球的最小间距；
  - 是否存在连杆机会等。
- 台面的上下文特征，例如：
  - 场上剩余的己方目标球和对手目标球数量；
  - 当前比分或领先/落后信息（如果有）；
  - 是否已经进入黑 8 阶段等。

最终，我们把“候选几何特征”和“上下文特征”拼接成一个定长向量，作为 CQR 模型的输入。目标输出是该候选在该上下文下的 Q 值近似，也就是我们在仿真中测到的 reward。

### 3. 模型训练：监督学习形式的 Q 回归

在有了大量 \((\text{特征向量}, \text{reward})\) 数据之后，CQR 的训练过程就变成了一个普通的监督学习任务：

- 选择一个回归模型（例如多层感知机、树模型等），初始化参数；
- 把采集到的样本分成训练集和验证集；
- 以均方误差、L1 损失或类似指标作为训练目标，让模型拟合 reward；
- 通过早停、正则化等手段防止过拟合；
- 在验证集上监控性能，直到模型在“预测候选质量”这件事上达到一个稳定水平。

由于 reward 完全由规则函数决定，没有策略分布漂移、优势估计噪声等问题，整个训练过程比 PPO 这种在线策略梯度要稳定得多，也更容易调参。

### 4. 在线决策：先筛候选，再依靠 CQR 打分

在实际对战时，CQR + Geometry 的在线决策流程是：

1. 当前台面给定；
2. 用与离线阶段同一套几何规则生成当前局面的候选击球；
3. 对每个候选计算几何特征和上下文特征，并拼接成输入向量；
4. 把这些向量依次送入已经训练好的 CQR 模型，得到每个候选的预测 Q 值；
5. 按 Q 值从高到低排序，取前几条最有前途的候选；
6. 只对这少数几条候选调用物理引擎做精细仿真，最后在它们中选出实际执行的一杆。

从直觉上看，这套流程就像是：

- 几何规则负责生成“物理上靠谱”的候选；
- CQR 模型负责从中挑出“在当前局面下值得一试”的少数几个；
- 物理引擎在最后把关，避免模型偶尔过于乐观的情况。

相比 PPO 这种直接从状态输出动作的端到端方法，CQR 把搜索空间限制在一个较小、几何上合理的候选集合里，同时又利用规则 reward 提供了清晰的监督信号，因此在样本效率和训练稳定性上都有明显优势。

## 优缺点小结

- 优点：
  - 候选由几何规则生成，天然带有“物理合理性”的先验，减少无效搜索；
  - reward 完全来自规则，训练阶段是稳定的监督学习问题，收敛快、可控；
  - 在线决策时只需对有限候选估计 Q 值，计算成本相对端到端 RL 更低；
  - 可以用同一套数据训练不同模型架构，便于迭代和对比。
- 缺点：
  - 需要事先收集较大规模的离线数据集，数据质量直接影响模型上限；
  - 模型在“训练分布之外”的局面可能表现不稳，存在泛化风险；
  - CQR 只能在给定候选中挑最好的一条，若候选生成阶段漏掉关键线路，模型也无能为力。

## 口播讲稿（约 2–3 分钟，可直接念）

这一页我介绍一下我们最终采用的强化学习风格方法，也就是 CQR 加上几何候选生成的方案。可以把它理解成：用规则和几何生成备选打法，用模型来学会打分，从而筛出最有希望的几条，再用物理引擎做精算。

具体来说，第一步是 Generator。我们还是用幽灵球的几何规则，从当前台面生成一批候选击球。每个候选不仅有对应的击球参数，还会抽取一套简单的几何特征，比如这条线路的切球角大不大、母球到目标球的距离、目标球到袋口的距离、中间是否有明显挡球、场上还剩多少颗己方球等等。

第二步是 Verifier，也就是环境。我们把这些候选一一交给物理引擎模拟一遍，用同一套规则 reward 函数给每个候选打分。这一步可以看成是在离线阶段给模型打标签：哪些候选是真正能进球、不太犯规的好球，哪些只是“看起来像样”但实际效果很差。

第三步是 CQR 模型训练。这里的“上下文”指的是台面的整体状态，比如剩余目标球的数量、领先还是落后等，我们把这些上下文信息和候选的几何特征拼在一起，当作模型的输入，训练一个回归模型去拟合对应的 Q 值，也就是期望得分。由于 reward 都是通过规则直接算出来的，这一步其实就是一个稳定的监督学习问题。

在测试或对战时，在线部分就很简单：当前台面来了，先用几何规则生成一批候选，计算各自的特征和上下文输入，送进 CQR 模型，得到每个候选的大致 Q 值。我们只取其中 Q 值最高的少数几条，再用物理引擎做少量精细模拟，最后选出最好的那一条来执行。

和 PPO 那种完全端到端的强化学习比，这种 CQR 加几何的方案更像是“人手写规则 + 学习一个聪明的打分器”。它把搜索空间限制在几何上合理的候选集合里，同时 reward 又是明确的规则打分，因此训练起来更稳定，样本效率也更高。
