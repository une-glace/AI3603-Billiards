# CQR + Geometry：基于上下文 Q 回归的强化学习方案

## 方法原理（简要版）

CQR（Contextual Q Regression）可以理解为“一种带上下文的 Q 函数回归”。在这个项目里，我们没有让模型直接在原始坐标上做决策，而是先用几何规则生成一批候选击球，再用机器学习模型从中挑选最有希望的一两个。

整体流程是：
- Generator：用幽灵球几何为当前台面生成若干个候选击球参数，每个候选都有一组手工几何特征（切球角、距离、是否被挡、目标球数等）；
- Verifier / Environment：把候选交给物理引擎模拟，按照同一套规则 reward 打分，得到每个候选的真实得分；
- CQR Model：用“几何特征 + 上下文信息（例如剩余目标球、当前局面等） → Q 值”的监督学习方式训练回归模型，让模型学会预测这类候选的大致质量；
- Online 使用时，只需对当前候选计算特征，分别送进 CQR 模型估计 Q 值，选取 Q 最大的少数几条，再用物理引擎做少量精细模拟确认。

相比 PPO，CQR 把搜索空间限制在“几何上合理的候选集合”里，同时用规则 reward 提供稳定的监督信号，因此样本效率更高、训练更稳定。

## 口播讲稿（约 2–3 分钟，可直接念）

这一页我介绍一下我们最终采用的强化学习风格方法，也就是 CQR 加上几何候选生成的方案。可以把它理解成：用规则和几何生成备选打法，用模型来学会打分，从而筛出最有希望的几条，再用物理引擎做精算。

具体来说，第一步是 Generator。我们还是用幽灵球的几何规则，从当前台面生成一批候选击球。每个候选不仅有对应的击球参数，还会抽取一套简单的几何特征，比如这条线路的切球角大不大、母球到目标球的距离、目标球到袋口的距离、中间是否有明显挡球、场上还剩多少颗己方球等等。

第二步是 Verifier，也就是环境。我们把这些候选一一交给物理引擎模拟一遍，用同一套规则 reward 函数给每个候选打分。这一步可以看成是在离线阶段给模型打标签：哪些候选是真正能进球、不太犯规的好球，哪些只是“看起来像样”但实际效果很差。

第三步是 CQR 模型训练。这里的“上下文”指的是台面的整体状态，比如剩余目标球的数量、领先还是落后等，我们把这些上下文信息和候选的几何特征拼在一起，当作模型的输入，训练一个回归模型去拟合对应的 Q 值，也就是期望得分。由于 reward 都是通过规则直接算出来的，这一步其实就是一个稳定的监督学习问题。

在测试或对战时，在线部分就很简单：当前台面来了，先用几何规则生成一批候选，计算各自的特征和上下文输入，送进 CQR 模型，得到每个候选的大致 Q 值。我们只取其中 Q 值最高的少数几条，再用物理引擎做少量精细模拟，最后选出最好的那一条来执行。

和 PPO 那种完全端到端的强化学习比，这种 CQR 加几何的方案更像是“人手写规则 + 学习一个聪明的打分器”。它把搜索空间限制在几何上合理的候选集合里，同时 reward 又是明确的规则打分，因此训练起来更稳定，样本效率也更高。
